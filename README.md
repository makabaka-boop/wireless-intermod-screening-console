# 无线话筒三阶互调排查台

演出彩排临时增加无线话筒时，单看每个载频都合法，但三阶互调产物（2A−B、2B−A）
可能贴近另一支话筒并造成现场爆音。本工具对整批频道做联调排查：

- **前端**：React + TypeScript（Vite），按受影响频道分组展示差值、产物与来源，并生成可复制摘要；
  清单旁另设候选名称/频率输入区，点「试加频道」可先评估临时借入话筒的增量影响；
  分析结果下方可从已登记频道中选择一支点「查找微调频点」，页面保留当前冲突分组并展示替换建议；
  结果顶部另可勾选一至三个重点频道（如主持人、主唱话筒）点「聚焦排查」，
  页面保留全部冲突分组，在顶部优先展示与重点频道相关的条目；
- **后端**：FastAPI，真实接口 `/api/analyze`（无任何假接口），所有输入错误都带行号、整批拒绝；
- **验收**：Docker Compose 中名为 `verify` 的一次性服务，跑完自动退出并给出验收结论。

## 快速开始

```bash
docker compose up --build
# 覆盖宿主端口：
WEB_PORT=9000 API_PORT=9001 docker compose up --build
```

- Web 页面：http://localhost:${WEB_PORT:-8080}
- API：http://localhost:${API_PORT:-8000}/api/health
- `verify` 容器退出码为 0 即验收通过：`docker compose up --build --abort-on-container-exit`

## 开发说明：判定口径

1. **精确整数换算**：输入频率（MHz，最多三位小数）先精确换算为整数 kHz
   （如 `500.100 MHz → 500100 kHz`），全程整数运算，杜绝浮点误差。
2. **产物计算**：对每一对不同频道 A、B，分别计算三阶互调产物 `2A−B` 与 `2B−A`。
3. **频段过滤**：只保留仍落在 **470.000–694.000 MHz**（含两端）内的产物。
4. **冲突判定**：产物与「生成它的两个频道之外」任一已分配频率相差
   **≤ 50 kHz（包括恰好 50 kHz）** 即记为冲突。
5. **去重与排序**：相同「产物 + 目标频道」只展示一次，但列全来源组合；
   来源组合内部按频道名称排序；总结果依次按 **目标频率 → 产物频率 → 目标名称** 排序。
6. **整批校验**：输入存在任何错误时返回 422 与全部错误（含行号），
   **不给出任何部分风险结果**。

### 频率示例

输入：

```
A 500.000
B 500.100
C 499.850
D 500.250
```

演算（单位 MHz）：

- `2A−B = 2×500.000 − 500.100 = 499.900`，距 C（499.850）**恰好 50 kHz → 冲突**；
- `2B−A = 500.200`，距 D（500.250）恰好 50 kHz → 冲突；
- `2A−C = 500.150`，距 B（500.100）恰好 50 kHz → 冲突；
- `2B−D = 499.950`，距 A（500.000）恰好 50 kHz → 冲突。

若把 C、D 改为 `499.849`、`500.251`，所有差值变为 51 kHz，**超出保护带，零项冲突**。

带外剔除示例：`A 470.020 / B 470.060` 的产物 `2A−B = 469.980 MHz` 虽距
`C 470.000` 仅 20 kHz，但产物已在频段之外，**不计冲突**。

### 候选试加（彩排临时借话筒）

页面在清单旁提供候选名称/频率输入区，点「试加频道」后仍调用 `/api/analyze`，
请求体额外携带 `"candidate": {"name": "...", "freq": "..."}`。后端复用频道解析、
整数 kHz 换算与冲突排序，对**基线清单**与**基线 + 候选**各分析一次，并以
「目标频道 + 产物频率 + 来源组合」构成稳定键比较两次结果：

- 顶层 `channels / conflicts / conflict_count / summary` **始终是基线清单的完整结果**，
  候选不写入正式清单；
- 响应增加 `candidate` 评估对象：

| 字段 | 说明 |
| ---- | ---- |
| `name` / `freq_khz` | 候选名称与精确整数 kHz |
| `status` | `safe`（无增量冲突）/ `risky`（为自身或既有频道引入冲突） |
| `baseline_conflict_count` / `merged_conflict_count` / `new_conflict_count` | 基线 / 合并后 / 增量冲突数 |
| `merged_channel_count` | 合并候选后的频道总数（超 32 直接拒绝） |
| `new_conflicts` | 候选加入后才出现的冲突，含全部来源 `sources` 与新增来源 `new_sources`，`target_is_candidate` 标识候选自身是否被命中 |
| `affected_channel_names` | 增量冲突涉及的全部受影响频道（含候选自身） |

候选错误（名称/频率与清单重复、名称以 `#` 开头——写入清单会被当作注释、格式非法、
频率越界、合并后超 32 频道、候选值非 `{name, freq}` 对象）固定返回
**行号 `0`** 的 422，前端据此只在候选输入区提示且**不覆盖上一次有效结果**；
清单正文非法时仍按原行号（从 1 开始）整批拒绝。未携带 `candidate`（或为 `null`）
时响应中不出现 `candidate` 字段，完全维持旧契约。

### 微调频点（演出前微调已登记话筒）

演出前发现当前清单存在互调冲突时，可微调其中一支已登记话筒，而不必反复手算。
先按原流程提交清单，再在分析结果下方从已登记频道中选择一支，点「查找微调频点」；
请求体额外携带 `"retune": "频道名称"`，仍调用 `/api/analyze`。后端在该频道
**原频率上下 500 kHz 内按 25 kHz 步长**枚举合法（仍在 470.000–694.000 MHz 内，
含两端边界候选）且未被其他频道占用的频点，复用整数 kHz 换算与冲突分析逐点重算
整表冲突，仅保留**严格优于当前清单**的方案，按
**冲突总数 → 移动距离 → 频率升序** 稳定排名，最多返回 5 条：

| 字段 | 说明 |
| ---- | ---- |
| `name` / `original_freq_khz` | 微调目标频道名称与原频率（整数 kHz） |
| `baseline_conflict_count` | 当前清单的冲突总数 |
| `suggestions` | 替换建议列表；每项含 `freq_khz`（替换频率）、`move_khz`（移动量）、`conflict_count`（替换后冲突数）、`reduced_count`（减少数量） |

- 顶层 `channels / conflicts / conflict_count / summary` **始终是当前清单的完整结果**，
  建议只作展示，**不会自动写回输入**；
- 若没有方案优于当前清单，`suggestions` 为空，页面明确显示「范围内无改善」；
- 微调频道名称不存在（或值非字符串）时返回 **行号 `-1`** 的 422，
  前端据此只在微调区提示且**不清空既有分析结果**；
- 清单本身非法仍按现有行号整批拒绝；未携带 `retune`（或为 `null`）时
  响应中不出现 `retune` 字段，完全维持旧契约。

### 聚焦排查（围绕重点话筒优先处理冲突）

大型演出频道较多时，协调员可围绕主持人、主唱等重点话筒快速判断哪些现有
冲突最值得先处理，而不改变完整分析口径。先按原流程提交清单，再从成功返回
的频道中勾选一至三个重点频道，点「聚焦排查」；请求体额外携带
`"focus": ["名称", ...]`，仍调用 `/api/analyze`。后端**复用现有冲突结果**
（不重新计算、不改写完整分组），按与重点频道的关系分级：

- **直接影响**（`direct`）：目标频道即重点频道的条目；
- **来源相关**（`source`）：仅来源组合包含重点频道的条目
  （目标优先，同一条目不重复计入）。

响应增加 `focus` 评估对象：

| 字段 | 说明 |
| ---- | ---- |
| `names` | 本次聚焦的重点频道（按请求顺序） |
| `direct_count` / `source_count` | 直接影响 / 来源相关条目数 |
| `entries` | 聚焦条目列表：直接影响整体在前、来源相关在后，两类内部各自保持完整结果的原有顺序（稳定排列）；每项保留原目标、产物、差值与全部来源组合，含多组来源的条目不拆分、不重复 |

- 顶层 `channels / conflicts / conflict_count / summary` **始终是当前清单的
  完整结果**，完整分组与可复制摘要不因聚焦而改写；页面用「直接影响 /
  来源相关」标签区分两类关系，并在顶部展示聚焦条目；
- 重点频道与当前冲突均无关联时 `entries` 为空，页面明确显示无关联；
- 重点频道名称不存在、重复、超过三个（或值非名称列表）时返回
  **行号 `-2`** 的 422，前端据此只在聚焦区提示且**保留上一次有效分析**；
- 清单本身非法仍按现有行号整批拒绝；未携带 `focus`（或为 `null`）时
  响应中不出现 `focus` 字段，候选试加与微调频点行为完全维持旧契约。

## 输入格式

每行一个频道：`名称 频率`（空白或中英文逗号分隔），支持 `#` 注释与空行。

- 频道数量 **2–32** 个，名称唯一（任意非空白、非逗号文本：可含点号、中文，长度不限）；
- 频率范围 **470.000–694.000 MHz**，最多三位小数，且互不重复
  （`500.1` 与 `500.100` 视为同一频率）。

所有错误统一返回 `{"errors": [{"line", "message"}]}` 结构（HTTP 422），
包括请求体缺失 `input` 字段等技术性错误——此时固定给出第 1 行提示，
页面不会拿到无法展示的技术错误。

错误响应示例（HTTP 422）：

```json
{
  "errors": [
    { "line": 1, "message": "频率「500.0005」非法：需为最多三位小数的 MHz 数值，例如 500.125" },
    { "line": 3, "message": "频率 469.000 MHz 超出允许范围 470.000–694.000 MHz" }
  ]
}
```

## API

| 方法 | 路径          | 说明                                       |
| ---- | ------------- | ------------------------------------------ |
| GET  | `/api/health` | 健康检查                                   |
| POST | `/api/analyze`| 提交 `{"input": "..."}`，可附带 `"candidate": {"name","freq"}` 试加候选、`"retune": "频道名称"` 查找微调频点或 `"focus": ["名称", ...]` 聚焦排查，返回冲突分析或 422 |

成功响应包含：`channels`（含行号）、`conflicts`（目标/产物/差值/来源组合）、
`conflict_count`、`summary`（可复制摘要文本）；携带合法候选时另含 `candidate`
评估对象，携带合法微调参数时另含 `retune` 评估对象，携带合法聚焦参数时另含
`focus` 评估对象（见上三节）。
前端经 nginx（或开发环境 vite）将 `/api` 反向代理到 api 服务，始终调用真实接口。

去重与排序、候选试加（安全无增量 / 风险命中自身与既有频道 / 重复越界指向候选区 /
合并超 32 / 旧请求字段不变）、微调频点（多个改善频点稳定排序且可复算 /
±500 kHz 与带缘边界候选参与计算 / 无改善返回空建议 / 未知频道指向微调区 /
清单非法整批拒绝 / 旧请求字段不变）、聚焦排查（直接影响排在来源相关之前 /
含多组来源的条目不拆分不重复 / 无相关冲突返回空结果 / 完整结果与摘要不改写 /
非法选择指向聚焦区 / 旧请求字段不变）、Web 页面与 `/api` 反代联调链路。
